# 项目教训

- 审计和精简 Skill 前，逐项核对原用途、触发条件、工作范围、输出与交付契约。文章中的效率建议不等于功能变更需求，不能据此缩小或扩大能力、重分配默认入口或改写评分政策。
- `wsl-windows-image` 只在 WSL 环境安装。保留直接转换路径并读图的流程，不添加宿主探测、挂载检查或跨宿主兼容步骤；部署范围明确改变时再调整。
- `index-project` 的核心用途包含代码变更后的主动增量维护：Agent 修改模块内容使索引失实时，应同步模块与项目索引。精简描述和工作流时必须保留这一触发，不能收窄为等待用户要求编辑文档。仅根级模式的落盘、续扫和完成检查应核对根内模块信息，不能要求不存在的模块文档。
- 按“改编、翻译”等来源类别撤销修改时，以 README 的来源说明界定目标，恢复本地基线并同步受影响的目录引用；保留原有中文化和范围外改动，不用上游原文替换本地版本。
