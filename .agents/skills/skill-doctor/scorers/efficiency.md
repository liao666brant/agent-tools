**评分标准**

你正在评估一份本地编码 Agent 会话的精简记录。考察抵达结果的完整成本：Agent 执行的步骤、造成的返工，以及消耗的人工注意力。评分基准是使用相同工具的称职工程师所需成本，而不是该 Agent 当时碰巧采用的能力上限。若更合适的工具、技能或检查本可避免某项错误，即使它在当前上下文中看似难免，也应计入，并在理由中指出原因。以下条目是常见浪费来源，并非穷尽清单；任何让本次运行成本高于合理水平的行为都应纳入判断。

评估：

- **错误导致的返工。** 因首次做错而重做，例如本可由本地检查发现的测试或构建失败、编辑错误文件，或误读需求后撤销改动。
- **人工成本。** 用户反复纠正或引导是最昂贵的浪费。提前提问成本很低；做错之后再问同一问题则不然。
- **信息收集。** 重复读取、运行或搜索已经得到的信息；本可定向搜索却从头到尾读取大文件。
- **例行步骤开销。** 对 Agent 的标准重复工作采用绕行方式，在已有直接路径时使用更多步骤、更多调用或更宽范围。不要只看本次成本：在技能或规则修复这一模式前，同样的可避免开销会在未来每次会话中重复。
- **批处理。** 本可同时进行的独立读取、搜索或工作流被拆成多个回合串行执行。
- **盲目尝试。** 不作实质改变地重试失败方案，或在读取代码或文档即可确定答案时猜测。只有在当时已有足够信息避免某条废弃路径时，才把它计为浪费。
- **验证时机。** 检查只运行一次，并足够早地在宣称完成前发现缺陷；不要推迟到交付后，也不要重复运行。

**理由**

用 1 至 3 句话指出主要浪费来源并给出大致次数，例如三轮修复测试、四次重复读取、两次用户重复纠正；同时指出可能修复的原因，例如技能缺失或薄弱、指令含糊、检查过晚。若已有技能本应避免这类浪费，应明确指出该技能。
