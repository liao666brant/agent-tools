# 技能改进准则

## 方法

1. 完成归因后，跨评分器和分类按根因聚类发现。
2. 按出现频率与严重程度的乘积确定优先级。
3. 提出改进前，针对当前仓库和 Agent 配置核验每项发现；无法核验的发现应舍弃。
4. 你正在修改另一个 Agent 的指令。改动应小而通用。编辑前，先用一句话说明预期行为规则及其归属位置，再做表达该规则的最小修改。
5. 优先**替换**现有指引，不要再追加一段重复内容。

## 何时提出修改

默认不提出修改。只有当具体指令缺失或错误，且修正后本可避免已评分失败时才继续。先问：一个遵循现有指令的称职 Agent 是否仍可能这样失败？若是，说明存在缺口；若否，暂不修改。

仅在以下条件全部成立时提出修改：

- 失败源于某个明确位置上的指令缺失、错误或规定不足，例如责任 Agent 的配置、某个技能或仓库内指引。
- 能指出该归属位置，以及其中本应写明的一条可复用规则。
- 如果该规则已存在并被遵守，已评分失败就不会发生。
- 同一缺口出现在多个来源会话中，或单次事件足够严重，已能证明契约缺失。

以下情况不要提出修改：

- 现有指令已经要求正确行为，只是模型没有遵守。
- 失败属于模型波动：相同提示、相同工具，却选择不同。
- 唯一可做的修改只是复述、增加模糊限定，或添加这些会话中的例子。
- 真正应修复的是产品、基础设施、评分器，或指令范围之外的代码。

如果没有任何建议达到上述门槛，就不要提出修改，并逐项说明原因；这同样是成功结果。推测性修改比不修改更糟。
