# image-analyzer

为当前主模型提供图像理解能力。两条路径，同一输出结构：

- **多模态主模型**：直接 Read 图片，按下方结构输出描述。
- **非多模态主模型**：用 Agent 工具委派 `sonnet` subagent 读图，sonnet 按同一结构返回文字描述，主模型据此继续。

统一结构保证：无论谁读图，主模型都拿到同样完整度的事实，下游推理不失真。

## 触发

用户要求分析图片、提取图中信息/文字/界面元素、理解截图/图表/架构图/流程图/示意图，或任何视觉内容理解需求。入参含图片路径（绝对路径优先）。

## 执行流程

### 1. 取得图片绝对路径

- 用户显式给路径 → 直接用。
- 用户贴图未给路径 → 在消息中找 `[Image: source: <path>]` 提取 path；无则向用户索要。
- 路径含变量/空格 → 双引号包裹。
- 多张图：收集全部路径，逐张处理（或一次委派多路径）。

### 2. 判定主模型是否多模态

满足任一即判定**非多模态**，走委派（步骤 3b）：
- Read 工具读图返回 `[Unsupported Image]` 或类似不支持信息。
- 用户消息中图占位符显示 `[Unsupported Image]`。
- 当前模型已知无视觉（如 kimi-k2.6 在不注入图字节的 harness 下、纯文本模型）。

否则走直读（步骤 3a）。

### 3a. 多模态：直接读图

用 Read 工具读取图片路径。读到视觉内容后，按步骤 4 的结构输出描述。

### 3b. 非多模态：委派 sonnet subagent 读图

用 Agent 工具：
- `subagent_type`: `general-purpose`
- `model`: `sonnet`
- `run_in_background`: `false`（同步，需结果后再继续）
- `prompt`: 用下方模板，替换 `{IMAGE_PATHS}`（多个路径用逗号分隔）和 `{TASK}`。

**prompt 模板：**

```
你具有视觉能力。请用 Read 工具读取图片：{IMAGE_PATHS}

读取后，针对以下任务进行详细描述：{TASK}

按以下结构返回描述（无对应内容的小节写「无」）：

## 文字
逐字转录图中所有可见文字（中文/英文/数字/符号），保留顺序与层级。表格用 markdown 表格还原。

## 界面元素
按钮、输入框、下拉、标签、菜单项、表格行列、图标含义、导航结构。

## 图表
类型（柱/折线/饼/散点/面积/热力…）、坐标轴标签与单位、数据点数值、图例、系列、趋势、标注。

## 布局与颜色
分区结构、主色调、强调色、状态色（成功/警告/错误）、字体风格、留白。

## 其他
任何与任务相关但未归入上述小节的细节。

只返回描述文本，不做额外推断或建议。描述需足够详尽，使无法看图的人能据此还原图内容。
```

subagent 返回的文本即图像描述。

### 4. 输出结构（两条路径统一）

无论直读还是委派，最终给用户/下游的描述都按此结构：

- **文字**：逐字转录，保留顺序与层级。表格用 markdown 表格。
- **界面元素**：按钮/输入框/标签/菜单/表格行列/图标含义/导航。
- **图表**：类型/坐标轴/单位/数据点数值/图例/系列/趋势/标注。
- **布局与颜色**：分区/主色调/强调色/状态色/字体/留白。
- **其他**：任务相关未归类细节。

结构目的：让下游推理有完整事实面，避免漏掉文字或数值这类客观信息。小节无内容写「无」，不要省略小节。

### 5. 主模型基于描述继续

- 描述（直读所得或 subagent 回传）作为事实依据。
- 按 user 原始需求完成后续推理/回答/代码改动。
- 走了委派时，向用户说明「视觉信息来自 sonnet subagent 读图」，便于判断可信度。
- 主模型不得伪造「我看到了图」——非多模态路径下，主模型只处理文字描述。

## 边界与回退

- 委派仅用于「读图并描述」，**不**让 subagent 完成整任务。主模型保留任务掌控。
- sonnet 也读不到图（Read 同样不支持）→ 如实告知用户当前环境无视觉通道，建议换支持视觉注入的客户端；不要编造内容。
- 描述不够用时，主模型可再次委派并补充追问点（如「重点看清表格第3列数值」）。
- 含敏感信息（凭证/密钥/个人信息）的图：委派等于把图传给 subagent，等同主模型自己读，无额外外泄；但若 subagent 经由外部 API，注意数据流向。
