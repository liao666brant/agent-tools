# 图像理解通道

通过主模型直读或视觉代理取得完整的图像描述，再由主模型完成原任务。两条路径使用同一描述结构；使用当前宿主实际提供的图像、文件或子代理能力，不固定不可用的工具名、模型名或参数。

## 取得图像

- 消息已经包含可读取的图片时直接使用，无需用户再提供本地路径。
- 用户给出文件路径时，使用图片读取工具所在环境可访问的路径；路径含空格时作为一个完整参数传递。
- 图像附件缺失或当前通道返回不支持时，才检查其他可用通道。多张图保留各自的来源和对应关系。

## 选择通道

主模型能够读取图像时，直接读图并按下方结构描述。主模型已知无视觉能力，或读图通道返回不支持时，使用宿主实际提供的视觉代理；按其真实参数调用，任务仅包含读图和描述，等待结果后再继续原任务。

委派的数据流须符合用户授权。不要把“本地代理进程”等同于本地推理；若需要把图片交给用户尚未授权的外部服务，先说明接收方和数据范围并取得授权。用户限定本地处理时，仅使用可确认在本地运行的通道。

没有可用通道时，说明缺少的能力，并请用户提供可访问的图片或所需信息；不重复要求已经提供且能够读取的附件。

## 统一描述结构

无论直读还是委派，交给用户或下游的图像描述都保留以下五节：

- **文字**：逐字转录所有可见文字、数字与符号，保留顺序和层级；表格用 Markdown 表格还原。
- **界面元素**：按钮、输入框、下拉、标签、菜单、表格行列、图标含义和导航结构。
- **图表**：类型、坐标轴标签与单位、数据点数值、图例、系列、趋势和标注。
- **布局与颜色**：分区、主色调、强调色、状态色、字体风格和留白。
- **其他**：与任务相关且未归入上述小节的细节。

没有对应内容的小节写“无”，不省略。看不清的文字和数值标记为无法辨认，不补造内容；不能把无法辨认写成没有内容。描述只承载视觉事实，不加入额外推断或建议，并应足够完整，让无法看图的主模型据此继续工作。

## 完成原任务

主模型基于描述完成用户原本的推理、回答或代码修改。通过委派取得的信息应注明来源，不声称自己看到了未直接读取的图片；描述不足时可再次委派，并明确需要补充的细节。
